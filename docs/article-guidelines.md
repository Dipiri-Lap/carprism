# 카프리즘 기사 품질 체크리스트 (2026-10-21)

강의자료(ref/)를 분석해 카프리즘에 맞게 걸러 낸 규칙이다. 신규 기사부터 적용하고, 기존 기사는 손볼 때만 맞춘다.
자동 점검: `node scripts/lint-article.js <slug>` 또는 `--date=YYYY-MM-DD` (경고 전용, 오류만 종료 코드 1).

## 0. 원칙
- 목표는 조회수가 아니라 **독자의 다음 행동**(이어 읽기, 공식 사이트 확인)이다. 광고 클릭을 유도하지 않는다.
- 팩트체크·출처 표기·정정 안내 운영이 이 사이트의 신뢰 자산이다. 속도보다 사실.
- AI는 초안과 구조를 맡고, 판단 기준(무엇을 쓰고 무엇을 확인할지)은 사람이 정한다.

## 1. 소재 선정 — "결정 직전" 우선
- 우선순위: 가격·견적·유지비·보험료·리스/렌트·중고차·리콜·비교 등 구매·계약 직전에 찾는 주제.
- 정보형(스펙 나열)보다 **무엇이 달라졌나 / 얼마를 더 내나 / 계약 전 무엇을 확인하나**로 각도를 잡는다.
- 건강·금융 상품(YMYL)은 자동차에 인접한 주제만, 가입·대출 권유 문구 없이 쓴다.

## 2. 정보 증분 게이트 (기획 단계, 필수)
같은 주제로 검색되는 상위 글 3개를 훑고, **그 글들에 없는 정보 1~3개**를 정한 뒤 본문에 넣는다.
예: 공식 가격표 직접 대조, 법령 조항, 직접 계산(총비용·차액), 자료마다 엇갈리는 수치 정리, 비교표, 확인 못 한 항목의 명시.
증분이 없는 기사는 쓰지 않는다(저가치 콘텐츠 판정 예방).

## 3. 제목
- **제목에 "(2026-10-21 기준)" 같은 기준일 괄호를 붙이지 않는다.** 기준일은 본문 첫 문단·표 캡션·확인 한계 박스에서 밝힌다. 근거 성격을 알리는 짧은 괄호("(보도 기준)", "(카프리즘 계산)")는 허용.
- 숫자·인용구·의문형 중 하나 이상 + 본문과 맞는 근거. "OO 총정리" 금지, 낚시 금지.
- 10유형을 한 배치 안에서 분산: 숫자, 비교, 문제 해결, 감정, 꿀팁, 시간·기간, 경고, 트렌드, 리스트.
- 카테고리별: 뉴스·신차는 이슈형 제목, 생활정보·중고차·보험·여행은 **검색 키워드를 앞에** 둔 문제 해결형.
- 부정 키워드(후회·손해·비용)는 숫자와 사실 근거가 있을 때만.

## 4. 도입부 3줄
공감 1줄(독자 상황) → 문제 1줄(궁금증) → 해결 암시 1줄(이 글이 답하는 것). 첫 문단은 2~3문장.

## 5. 본문 구조
- H2 5개 이상. **"개요/정리" 같은 밋밋한 소제목 금지**: 질문·수치·키워드가 들어가게, 순서는 검색자가 다음에 궁금해할 순서.
- H2 바로 아래 첫 줄에 **직답**을 둔다(질문-직답-근거).
- 문단은 2~3문장, 길어도 5문장 이하. 섹션 끝에 다음 섹션으로 이어지는 한 줄.
- 표는 필수에 가깝다. **표 바로 뒤에 "왜 이런 차이가 나는지" 해설 한 줄.**
- 신차·리뷰·비교는 **아쉬운 점/주의할 점** 소제목을 넣어 장단점을 균형 있게.
- 계약·구매형(중고차·리스·보험)은 "계약 전 확인 질문 5가지" checkpoint-box.
- 사례·후기: 실재하는 공식 자료·보도·통계만. 지어낸 1인칭 경험, 시승하지 않은 차의 시승 표현 금지.

## 5-1. "카프리즘 시선" 해석 박스 (분석형 기사 한정)
스펙 나열 대신 "왜 그런가, 구매자에게 무슨 뜻인가"를 1~2문단으로 짚는 박스. 사이트만의 관점을 만드는 거의 유일한 장치다.
```html
<div class="insight-box">
  <p class="insight-title">카프리즘 시선</p>
  <p>…기사에 이미 나온 공식 수치에서 계산·비교해 나온 해석 1~2문단…</p>
</div>
```
- 쓸 곳: 가격·비교·제도 변경·시장 분석 기사. 속보성 단순 보도, 여행 정보형에는 억지로 넣지 않는다. 기사당 1개.
- 조건: **기사 본문에 이미 제시한 공식 수치**에서 나온 해석만. 예) "같은 H-Pick끼리는 61만 원 내렸다 → 이름이 같아도 사양 구성이 달라 단순 비교는 위험하다."
- 금지: "사야 한다/사지 말아야 한다" 식 결론, 구매·가입 권유, 시승·사용 경험처럼 읽히는 문장, 근거 없는 전망·단정, 매끈하지만 내용 없는 일반론.
- 위치: 비교표·가격표 바로 뒤 또는 정리(summary-box) 직전. 광고 단위 바로 옆에는 두지 않는다.
- 팩트체크 대상에 포함한다(박스 안 해석의 근거 수치가 본문에 있는지).

## 6. 마무리와 CTA 박스
- 정리(summary-box) 다음에 **CTA 박스(`spec.cta`)**: 이어 읽을 내부 기사 1개(1차 버튼) + 필요하면 공식 사이트(2차 버튼).
- 문구: 행동이 드러나는 2~5어절("…비교 보기", "…확인하기"처럼 동사형으로 끝나게), 선택 제안형, 이유를 먼저(박스 본문에 이유를 쓰고 버튼은 짧게). 결론을 숨기지 않는다.
- 금지: 광고 클릭 유도, 광고처럼 보이는 버튼, 허위 긴급성("오늘이 가장 쌉니다", "선착순"), 정보 일부를 일부러 빼는 "미완성" 전략, 댓글 유도.
```json
"cta": {
  "title": "다음에 볼 기사",
  "text": "리스 만기 때 얼마를 더 내야 하는지가 궁금하다면 이어서 확인해 보세요.",
  "primary":   { "label": "리스 만기 비용 비교 보기", "href": "<실존 slug>.html" },
  "secondary": { "label": "공식 가격표 확인하기",     "href": "https://…" }
}
```
build-article.js 는 `href` 의 내부 기사 존재 여부를 검사한다.

## 7. 광고 위치
- 본문 중간 `<!--AD-->` 1~2개: 핵심 정보 직후나 표 뒤처럼 흐름이 자연스럽게 끊기는 곳. 기계적 N문단 간격 금지.
- CTA 박스와 광고 단위는 충분히 떨어뜨린다(CSS 여백 56~72px). 광고를 늘리지 않는다.

## 8. 이미지
- 최소 4장, 목표 8장 이상(자동차·여행은 이미지 비중이 큰 카테고리라 "이미지는 적게"라는 강의 기조는 따르지 않는다).
- WebP, 가로 1200px 이하. 강의 기준 100KB 이하는 신규 이미지에서 가능한 만큼.

## 9. 발행 리듬
- 같은 날 대량 발행은 시간만 나누고 날짜는 오늘로 둔다(기존 원칙). 며칠에 걸친 예약 발행은 사이트맵 lastmod·RSS 정합을 따로 검토한 뒤에만.

## 10. 쓰면 안 되는 것 (강의에 있었지만 제외)
- 광고 클릭 유도·광고 인접 버튼 위장, 허위 후기·가상 사례, 허위 긴급성, 공포 과장, 제목과 다른 본문.
- 의도적 오타·비속어·추임새·이모지 남발(AI 티 제거 목적), 표절률 낮추기용 문장 바꾸기.
- 근거 불명 통계(체류 4분, CTR 8.2% 등)와 강의 예시 문장의 복사.
- 네이버 포털 알고리즘 전제 전략(구글 검색 중심인 이 사이트에는 맞지 않음), 의료·시술·금융 상품 후기 양산.
